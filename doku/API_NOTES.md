# API notes and validation

Official Autodesk documentation and the installed Fusion Python API definitions were checked on 2026-11-03.

## Implemented prototype

The owner's Python template still owns run/stop, command registration and retained event handlers. BearingNest is registered in `FusionSolidEnvironment / SolidCreatePanel`. The visible command name appends `VERSION` from `version.py`; IDs remain stable.

The dialog has four tabs: Bearing Seat, Bearing Catalog, Settings and Info. Bearing Seat collects face/position selections and manual dimensions. Unit inputs use explicit mm/degrees. Fusion's internal length/angle values are converted to mm/degrees before validation, and contour coordinates are converted to cm only at the sketch API boundary.

For 0.4.6, Autodesk's [ValueCommandInput properties](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_ValueCommandInput.htm), [table creation and column ratios](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_CommandInputs_addTableCommandInput.htm), [table cell assignment](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_TableCommandInput_addCommandInput.htm) and [table presentation styles](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_TablePresentationStyles.htm) were checked on 2026-11-07. Value inputs have no documented pixel-width setter. Numeric rows therefore use full-width transparent tables with 50:50 label/value columns, restored at the owner's request in 0.4.8, a read-only string label and the original ValueCommandInput in the second cell. The same layout helper also places land-count/shaft-mode dropdowns and the provisional Preview/Inner-ring relief checkboxes in the right column. SelectionCommandInputs remain outside tables, as required by the API. Rows share one table per value-bearing group/tab (9 tables for 42 rows). During construction, each table sets both minimumVisibleRows and maximumVisibleRows to its known row count, without a nested scrollbar, and displays no grid. This reduces native layout containers; the effect on expansion speed still requires a Fusion comparison. Group expansion is ignored by the inputChanged handler, while the normal executePreview transaction lifecycle is preserved. Both cells expose localized tooltip text. This preserves expression handling and input IDs; native Fusion rendering at narrow sizes remains unverified.

`contour_geometry.py` is the shared pure contour implementation. The documentation SVG generator uses that same code. The Fusion adapter creates an empty face sketch with `addWithoutEdges`, then builds exact lines and three-point circular arcs. Curves are fixed; version 0.2.0 edits by rebuilding the last complete creation batch from its snapshot.

The sketch normal is compared with the outward face normal (including `isParamReversed`) to select the inward extrusion direction. A new-body extrusion produces the exact contour tool. Temporary BRep intersections compare that tool's full volume with its intersection volume inside the selected body; a second check shifts the tool inward by 0.001 mm to verify a floor. Every tool is hidden during validation. All positions and their pairwise envelope differences are checked before the first cut. Validation extrusions are then deleted, and direct cut extrusions use explicit participantBodies to affect only the selected body.

Preview starts enabled in 0.4.0 and can be switched off. Its handler sets `isValidResult = False`, so execute rebuilds from the original model and writes the seat snapshot on the final cut. Execute errors set `executeFailed` and `executeFailedMessage` to abort the command transaction even though the template wrapper catches exceptions. The adapter also removes newly created features on failure, including preview failures. Live rollback and cleanup still require acceptance testing.

The supported scope is one root-component solid body in a parametric design. Proxy/child-component placements are rejected. Multiple positions on one face share the same settings; unlimited position selection uses setSelectionLimits(1, 0). Version 0.1.6 added optional shaft and inner-ring operations, 0.2.0 optional chamfer and constrained batch editing, 0.3.0 catalog/profile storage, and 0.4.0 diagnostic markers and conservative advisory wall probes.

Generated contour sketches remain visible with areProfilesShown enabled through profile construction and the final cut, then are hidden using isVisible=False. Their profile calculation stays enabled for feature recomputation. On successful execute, selected point sketches also have only their profile fills disabled; their points, curves and visibility remain unchanged. Failed batches restore the original fill flags. Preview does not change source sketch fill preferences. Removing retained coplanar tools and disabling profile overlays addresses possible sources of the reported triangles; the exact cause has not been established from the screenshot alone. Existing seats are not rebuilt automatically.

The 0.1.4 screenshot identifies a concrete profile-construction failure at position 1. Version 0.1.5 removes the premature profile/visibility suppression introduced in 0.1.3, restoring the 0.1.2 construction order. The profile regression substitute now depends on profile-display and deferred-compute state rather than always returning one profile. The owner confirmed preview and creation working in 0.1.5; the supplied screenshots are embedded in [the screenshot guide](SCREENSHOTS.md).

## Optional clearances in 0.1.6

Each shaft/inner-ring operation has a circular sketch with profiles enabled. Blind shaft depth starts at the selected face; inner-ring relief uses a signed OffsetStartDefinition at the seat floor. Each circle sketch independently resolves its inward normal. Through All uses ThroughAllExtentDefinition from the installed Autodesk SDK, with explicit participantBodies. Its finite validation envelope covers the projected body extent plus 1 mm and intentionally allows the shaft exit. Seat, blind shaft and inner-ring tools still require full containment and floor checks. Every tool participates in pairwise batch overlap checks before any cut. Unknown bearing inner-ring dimensions are not inferred from the manual relief diameter.

## Preview diagnostics API choices in 0.4.0

Markers use one dialog-owned [custom graphics group](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_CustomGraphicsGroups_add.htm), packed world-space [coordinates in centimetres](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_CustomGraphicsCoordinates_create.htm), and independent [line segments](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_CustomGraphicsGroup_addLines.htm). Solid colors indicate error/warning/other candidates; [show-through](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_CustomGraphicsShowThroughColorEffect_create.htm) keeps them visible through the body. Lines are explicitly [nonselectable](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_CustomGraphicsEntity_isSelectable.htm). Cleanup calls [deleteMe](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_CustomGraphicsGroup_deleteMe.htm), checks its result, and retains failed ownership for retry. Validation callbacks do not write controls or create graphics.

Advisory margins use [TemporaryBRepManager.createCylinderOrCone](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_TemporaryBRepManager_createCylinderOrCone.htm) and the existing temporary containment/difference checks. Probes do not create document features. They enclose and enlarge each finite cutting region and test nearby proposed envelopes; failures warn without weakening strict cut validation. Through All shafts are excluded from wall probes. See [probe limits and acceptance](PREVIEW_AND_WALLS.md). These API choices were checked against official Autodesk documentation; native rendering and warning behavior remain pending.

## Chamfer and edit API choices in 0.2.0

The native chamfer uses ChamferFeatures.createInput2 and addEqualDistanceChamferEdgeSet with explicit mm units and tangent-chain expansion disabled. Candidate edges come only from the seat cut side faces and must lie on the original placement plane at both curve endpoints and midpoint. Warning/error features, multiple resulting bodies and no material removal are rejected. The full seat depth remains unchanged. Chamfer is off by default; 0.2-0.6 mm are trial sizes, not guaranteed feasible for every contour.

Before any cut, an enclosing cylinder with diameter contact + 2 * (radial relief + chamfer) and depth chamfer participates in containment and cross-seat overlap checks. It is deliberately conservative: it can reject feasible close-to-edge or close-to-seat placements. Its validation extrusion and sketch are removed rather than retained as final cuts. Fusion's chamfer kernel checks the actual resulting contour; failures reject the whole batch.

Editing uses TimelineObject.index, parentGroup and writable isSuppressed with Timeline.count/markerPosition to guard the last complete batch. Sketches remain available while old cuts are suppressed. See PERSISTENCE_PROTOTYPE.md for transaction and legacy limitations. API members were checked against the installed Autodesk SDK definitions and current official references; this is not live geometry acceptance.

## Preview-dependent dialog timing (0.4.7)

The owner reports remaining 1–2 second group toggles only with active geometry preview. Callback timing is buffered in memory (aggregate count/total/max and the last 32 callback IDs/times) and reported through Application.log after successful dialog cleanup. The default log destination is the Text Commands window; no parameter values are logged and no logging runs during toggles. Python handler time excludes native layout and Fusion's pre-callback preview rollback. This distinction follows Autodesk's documented preview transaction lifecycle; timings cannot by themselves measure rollback or total click latency.

## Validated graphics replay for layout changes (0.4.7)

The owner trace shows executePreview after group input changes even when inputChanged ignores them. Repeated preview handlers take approximately 228–234 ms; native rollback/layout remains outside the measurement. Simply returning early would lose the preview after Fusion rolls back the previous transaction.

For new-seat creation, retain a TemporaryBRepManager.copy of the successfully validated final feature body, not references to temporary features. After a group-only change, CustomGraphicsGroup.addBRepBody displays this detached copy. Source-body opacity is temporarily zero while its light bulb remains unchanged, preserving native selection availability. ## Deferred preview and selection preservation (0.4.7, supersedes synchronous request)

The owner reports selection loss after value changes with the synchronous request revision. The latest revision queues Command.doExecutePreview through a command-owned custom event instead of nesting it in inputChanged. Autodesk documents that [fireCustomEvent](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_Application_fireCustomEvent.htm) queues its handler until Fusion is idle. Requests are coalesced, naturally dispatched preview cancels redundant queued work, and lifecycle cleanup cancels/unregisters the custom event.

Capture face and ordered position entities/tokens before feedback/appearance cleanup. Within the guarded preview transition, restore selections if the host dropped them; resolve invalidated references uniquely before writing any selection input. Skip retained selections so temporary cut topology is not re-resolved unnecessarily. Recheck after the forced host callback for a host clearing selections on return. A deliberate selection event cancels the pending snapshot/request, so a user-removed point is not silently re-added. Selection restoration uses [SelectionCommandInput.addSelection](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_SelectionCommandInput_addSelection.htm) only after command creation and outside validateInputs; no selection focus is changed by restoration. These APIs were checked on 2026-11-07.

Automated tests now simulate actual selection loss before/after the callback, invalidated token resolution, ambiguity rejection, multiple points, intentional deselection, queued request coalescing/cancellation and cleanup. The prior tests only retained selection counts through a synchronous mocked callback and did not cover the reported native failure. The new behavior still requires Fusion confirmation.
## Native fireCustomEvent return mismatch (0.4.7)

On 2026-11-07 the running owner's Fusion dialog was inspected using Windows Computer Use. Face and point inputs each showed one selection, while the status read Could not queue the BearingNest preview. A temporary, model-independent console test registered a custom event and a retained CustomEventHandler. Registration/handler addition succeeded, but both fireCustomEvent(id) and fireCustomEvent(id, '') returned False. The handler was subsequently called. A worker-thread test likewise returned False and was delivered. Cleanup removed the diagnostic handler and unregistered the event (both returned True). Text Commands was restored to Txt mode. No model geometry or installed add-in files were changed by the agent.

This contradicts the documented boolean contract in [Application.fireCustomEvent](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_Application_fireCustomEvent.htm). Pending work must therefore be consumed by actual callback delivery or explicit lifecycle cancellation, not by interpreting False as a queue rejection. Thrown exceptions still reset pending state and report failure. DeferredPreview now also retains the registered CustomEvent wrapper until cleanup. No worker is used by the implementation. A regression test simulates a False-returning host that nevertheless queues/delivers the event. The native mismatch is verified; the corrected full dialog still needs an updated preview/selection trial.
## Source-selection tokens before cut previews (0.4.7)

The owner's Preview-off report was reproduced directly in Fusion on 2026-11-07 using a temporary new-seat preview: a selected face and point produced a valid preview; switching it off left the point selected, removed the face and displayed 3: invalid argument selection. The test was cancelled, with no seats applied or installed files changed.

The existing restoration snapshot read entity tokens after feature preview had already modified face topology. The correction retains a per-selector source-token baseline captured immediately before feature creation, carries it across later toggles/value edits, and invalidates it on explicit edits to that selector. Batch changes and reactivation invalidate all baselines. Restoration still uniquely resolves tokens after rollback, and no token-string comparison is used as entity identity. Tests simulate a face token changing during preview and verify that Preview off resolves only the original source token, not the temporary cut token. They also verify that explicit face replacement/removal discards the prior baseline. The failure is verified natively; the corrected behavior still needs an updated native trial.
## Action buttons and native selection alignment (0.4.8)

BoolValueCommandInput action buttons now share right-column cells at 50:50, including catalog/profile saves and deletes, reset, import/export and the named catalog footer. SelectionCommandInput is explicitly excluded from [TableCommandInput](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_TableCommandInput.htm). The face and position selectors therefore retain their original native placement and behavior; exact right-column alignment of these two requested controls is not implemented. Hidden selectors/modal proxy buttons were not introduced because they would change the selection workflow and risk the recently corrected preview/selection lifecycle. Native action-button rendering remains to be checked; automated tests cover cell placement, original button identity/tooltips and exclusion of selection inputs from tables.
